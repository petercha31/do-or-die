# do-or-die 초기 기안

## 1. 프로젝트 개요

| 항목 | 내용 |
| --- | --- |
| 프로젝트명 | do-or-die |
| 한 줄 설명 | 해야 할 일을 입력하면 AI가 인증 방법을 정하고, 그 방법으로 달성을 확인하는 앱 |
| 작성일 | 2026-10-06 |
| 상태 | 초안 |

첫 버전은 반복 없이, 목표 한 건을 입력하고 달성 여부를 체크하는 흐름만 다룬다.

구현 기술은 이 기안서에 두지 않는다. [`docs/technical/`](technical/README.md)에서 따로 관리한다.

## 2. 배경과 목적

할 일 목록은 체크만으로 완료가 된다. 실제로 했는지와 완료 표시가 분리되어 있다.

증명 방식은 목표마다 다르다. 장보기는 영수증이 맞고, 집중 시간은 그 구간 동안 휴대폰을 쓰지 못하게 하는 쪽이 맞다. 이 설계를 사용자가 매번 하면 입력이 무거워진다.

이 앱은 입력을 짧게 유지하고, 인증 방법 설계를 AI에 맡긴다. 사용자는 AI가 돌려준 방법대로 증명하고 달성을 체크한다.

## 3. 대상 사용자

스스로 잡은 약속을 미루기 쉬운 사람. 오늘 해야 할 일 한 건을, 했다고 표시하기 전에 증거나 제약으로 남기고 싶은 사람.

지금 쓰는 할 일 앱은 완료 버튼을 누르면 끝이 난다. 인증 앱은 사진 규칙을 사용자가 직접 정해야 하는 경우가 많다.

## 4. 핵심 가치

1. 목표는 한 번 입력하면 된다.
2. 그 목표에 맞는 인증 방법을 AI가 정해서 알려 준다.
3. 달성 체크는 그 인증을 거친 뒤에 남는다.

## 5. 사용자 흐름

1. 사용자가 목표를 입력한다. 시각, 장소, 해야 할 내용이 문장에 들어간다.
2. 앱이 그 문장을 AI에 보내고, 인증 방법 응답을 받는다.
3. 앱이 응답을 사용자 말로 보여 준다. 무엇을 찍을지, 무엇을 잠글지, 어기면 무엇이 생기는지.
4. 사용자가 그 방법으로 인증한다.
5. 달성을 체크한다.

주기, 반복, 연속 달성 기록은 이 흐름에 넣지 않는다.

## 6. 기준 사례

### 장보기 — 영수증 사진

입력:

> 17:00에 마트 장보러 가서 물품 리스트대로 사 오기

AI가 돌려줄 인증:

- 방법: 사진
- 증거: 영수증
- 안내: 계산이 끝난 영수증을 찍는다. 결제 시각과 구매 품목이 보여야 한다.
- 볼 기준: 리스트의 물건이 영수증에 있는지, 결제 시각이 17:00 근처인지

### 업무 집중 — 휴대폰 잠금과 패널티

입력:

> 13:00–15:00 업무 집중

AI가 돌려줄 인증:

- 방법: 휴대폰 잠금
- 구간: 13:00–15:00
- 안내: 이 시간 동안 휴대폰 사용을 잠근다.
- 패널티: 강제로 풀면 기부

사진이 기본 인증이다. 집중처럼 사진보다 제약이 맞는 목표에는 AI가 잠금과 패널티를 고른다.

## 7. AI 인증 응답

AI의 역할은 목표를 읽고, 어떤 식으로 인증할지 정해서 응답하는 것이다. 응답에는 아래 항목이 들어간다.

| 항목 | 의미 |
| --- | --- |
| method | 인증 방법. 첫 버전에서 쓰는 값은 `photo`, `phone_lock` |
| summary | 한 줄 요약 |
| instruction | 사용자에게 보여줄 안내 |
| evidence | 내야 하는 증거. 사진이 아니면 비운다 |
| criteria | 달성으로 볼 조건 |
| window | 목표 시각 또는 시작–종료 |
| penalty | 어겼을 때의 불이익. 없으면 비운다 |

장보기 응답 예:

```json
{
  "method": "photo",
  "summary": "영수증 사진으로 인증",
  "instruction": "계산이 끝난 영수증을 찍어 주세요. 결제 시각과 구매 품목이 보여야 합니다.",
  "evidence": "영수증 사진",
  "criteria": [
    "목표 물품이 영수증에 있다",
    "결제 시각이 17:00 근처이다"
  ],
  "window": { "at": "17:00" },
  "penalty": null
}
```

집중 응답 예:

```json
{
  "method": "phone_lock",
  "summary": "집중 시간 동안 휴대폰 잠금",
  "instruction": "13:00부터 15:00까지 휴대폰 사용을 잠급니다. 강제로 풀면 기부가 발생합니다.",
  "evidence": null,
  "criteria": [
    "15:00까지 잠금을 유지했다"
  ],
  "window": { "start": "13:00", "end": "15:00" },
  "penalty": {
    "type": "donation",
    "trigger": "강제 해제"
  }
}
```

## 8. 범위

### 이번 기안에 포함

- 반복 없는 목표 한 건 입력
- AI 인증 방법 응답을 받아 사용자에게 표시
- 사진 인증과 달성 체크
- 휴대폰 잠금, 강제 해제 시 기부 패널티를 인증 유형으로 정의

### 이번 기안에서 제외

- 매일, 매주 같은 반복 목표
- 여러 목표의 통계, 순위, 소셜 피드
- 인증 방법의 사용자 직접 편집
- PC 실행

## 9. 화면

1. **목표 입력.** 문장 하나와 등록.
2. **인증 안내.** AI 응답의 요약, 안내, 조건, 패널티.
3. **인증.** 사진이면 촬영 또는 업로드. 잠금이면 시작과 강제 해제.
4. **달성.** 인증을 마친 목표를 달성으로 남긴다.

## 10. 제약과 가정

가정:

- 목표 입력은 자유 문장 하나다.
- 사진 인증이 기본이고, AI가 목표에 따라 다른 방법을 고를 수 있다.
- 달성 체크는 안내된 인증을 수행한 뒤 남긴다.

아직 구현으로 확정하지 않은 제약:

- 기부는 금액, 단체, 결제, 강제 해제의 정의가 있어야 실행된다. 강제 해제에는 잠금 풀기, 앱 삭제, 기기 재시작이 들어갈 수 있다.
- 영수증 사진의 합격 여부를 사용자가 확인할지, AI가 사진을 보고 판정할지는 이 기안에서 정하지 않았다. 지금 AI가 맡는 일은 인증 방법을 정하는 응답이다.

## 11. 열린 질문

- 물품 리스트를 목표 문장 안에 쓸지, 별도 목록으로 붙일지
- 사진 합격 판정을 사용자 확인으로 둘지, AI 판독으로 둘지
- 잠금의 단위를 앱 사용 제한으로 둘지, 기기 사용 제한으로 둘지
- 기부 금액, 받는 곳, 결제 수단, 취소 가능 여부
- 목표를 수정, 취소, 실패로 바꾸는 규칙
