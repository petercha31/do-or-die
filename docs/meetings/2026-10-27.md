# 2026-10-27

## 로그인과 서버 데이터베이스

계정과 목표의 원본은 서버에 둔다. 앱은 데이터베이스에 직접 붙지 않고, 로그인 토큰으로 API만 호출한다. 휴대폰의 `goals.db`는 목록을 바로 보여 주기 위한 캐시로 남긴다.

### 저장 위치

| 데이터 | 위치 |
| --- | --- |
| 계정, 목표, 시작·종료 시각, 인증 방법, 판정 | 서버 데이터베이스 |
| 목록 표시용 복사본 | 휴대폰 SQLite |
| 시작 5분 전 알림, 유튜브 통제 | 기기. 서버 목표를 받은 뒤 예약 |

### 데이터베이스

PostgreSQL을 쓴다. `users`는 `id`, `kakaoId`, `email`, `createdAt`을 가진다. 이메일은 카카오가 알려 준 경우에만 있다. `goals`는 `StoredGoal` 키만 API로 내보낸다. 소유 계정은 응답에 넣지 않고, 서버가 토큰과 행을 연결하는 컬럼으로만 둔다.

한 사용자는 자기 목표만 읽고 지운다. 전체 지우기는 그 계정의 목표만 지운다.

인증 사진은 판정이 끝나면 서버에 남기지 않는다. 서버가 사진을 받아 Gemini에 넘기고, 통과·실패와 이유만 저장한다. Gemini API 키는 앱 안의 `.env`에서 서버로 옮긴다.

### 로그인

로그인은 카카오 로그인으로 한다. 앱이 카카오 인증을 마치면 서버가 카카오 회원 번호를 확인하고, 그 번호의 계정이 없으면 만든다. 서버는 우리 토큰을 주고, 앱은 그 토큰을 안전 저장소에 넣는다. 이후 목표 요청마다 이 토큰을 보낸다.

### 앱 동작

1. 앱을 열면 저장된 토큰으로 사용자를 확인한다. 없으면 로그인 화면이다.
2. 로그인되면 서버 목표를 받아 로컬 목록을 다시 그린다. 남은 시간과 시작 알림은 받은 시작시각으로 계산한다.
3. 등록, 판정 저장, 전체 지우기는 서버에 먼저 반영하고, 성공한 뒤에 로컬 목록을 바꾼다.
4. 네트워크가 없으면 그 동작은 실패로 알린다. 오프라인 등록과 나중 동기화는 넣지 않는다.

이미 휴대폰에만 있는 목표는 첫 로그인 때 그 계정으로 한 번 올릴 수 있게 둔다. 올리지 않으면 서버에는 빈 목록으로 시작한다.

### 서버 데이터베이스 활성화 순서

앱은 이 순서가 끝나기 전까지 로컬 SQLite만 쓴다.

1. 로컬 PostgreSQL을 띄우고, `users` 마이그레이션을 저장소에 넣어 적용한다. 운영 데이터베이스는 이 스키마가 로컬에서 재현된 뒤에 만든다.
2. 카카오 로그인으로 계정이 저장되는지 확인한다.
3. `goals` 테이블을 `StoredGoal` 키로 마이그레이션한다.
4. 토큰이 있는 요청만 그 계정의 목표를 등록, 조회, 판정 저장, 전체 삭제할 수 있는지 확인한다.
5. 여기까지가 서버 데이터베이스 활성화다.
6. 그 다음 앱에 로그인을 붙이고, 서버 반영이 성공한 뒤에만 로컬 목록을 바꾼다.
7. 휴대폰에만 있던 목표는 첫 로그인 때 한 번 올린다.
8. Gemini 호출과 사진 판정은 목표 저장이 서버에서 된 뒤에 서버로 옮긴다.

시작 5분 전 알림은 앱이 목표를 저장한 뒤 기기에서 예약하는 지금 방식을 유지한다.

## 저장 키

데이터베이스 컬럼은 밑줄 이름을 쓴다. API가 앱에 줄 때는 `StoredGoal` 필드 이름으로 바꾼다.

`StoredGoal`에는 `userId`를 두지 않는다. 앱은 로그인 토큰의 계정 목표만 받고, 목표 객체마다 소유자를 다시 적지 않는다. 서버는 그 토큰으로 행을 가려 조회한다.

| 키 | 내용 |
| --- | --- |
| `id` | 목표 식별자 |
| `text` | 목표 문장 |
| `verification` | 고른 인증 방법 제목 |
| `responseJson` | 고른 인증 방법 JSON |
| `createdAt` | 등록 시각 |
| `startAt` | 시작시각 |
| `endAt` | 종료시각 |
| `verdict` | 판정. `pass`, `fail`, `unclear`, 또는 빈 값 |
| `verdictReason` | 판정 이유 |
| `verifiedAt` | 판정 시각 |

계정 클래스는 아직 없다. API 키는 `id`, `kakaoId`, `email`, `createdAt`이다. 클래스를 만들면 그 필드 이름을 키로 쓴다.

## 스키마

설명은 [`docs/technical/schema.md`](../technical/schema.md)에 둔다. 지금 필요한 테이블은 `users`와 `goals`다. 로그인 토큰은 테이블로 두지 않는다. 시작시각이나 종료시각이 없는 기존 로컬 목표는 올리지 않는다.

```sql
create table users (
  id bigint generated always as identity primary key,
  kakao_id bigint not null unique,
  email text unique,
  created_at timestamptz not null default now()
);

create table goals (
  id bigint generated always as identity primary key,
  user_id bigint not null references users (id),
  text text not null,
  verification text not null,
  response_json text not null,
  created_at timestamptz not null default now(),
  start_at timestamptz not null,
  end_at timestamptz not null,
  verdict text not null default '',
  verdict_reason text not null default '',
  verified_at timestamptz,
  check (end_at >= start_at),
  check (verdict in ('', 'pass', 'fail', 'unclear'))
);

create index goals_user_created_idx on goals (user_id, created_at desc);
```

`kakao_id`로 계정을 찾는다. `email`은 카카오가 알려 준 경우에만 소문자로 저장한다. `goals.user_id`는 서버가 토큰과 행을 연결하는 컬럼이며 API 응답에 넣지 않는다.

| 컬럼 | API 키 |
| --- | --- |
| `goals.text` | `text` |
| `goals.verification` | `verification` |
| `goals.response_json` | `responseJson` |
| `goals.created_at` | `createdAt` |
| `goals.start_at` | `startAt` |
| `goals.end_at` | `endAt` |
| `goals.verdict` | `verdict` |
| `goals.verdict_reason` | `verdictReason` |
| `goals.verified_at` | `verifiedAt` |
| `users.kakao_id` | `kakaoId` |
| `users.email` | `email` |
| `users.created_at` | `createdAt` |
