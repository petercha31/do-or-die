## 카카오 로그인·토큰

- 로그인은 카카오 Flutter SDK가 담당한다. 액세스·리프레시 토큰은 SDK `TokenManager`(기본 구현은 `SharedPreferences`에 AES 암호화 저장)에 둔다. 앱이 토큰을 직접 Preference에 쓰는 구조는 아니다.
- 서버가 사용자를 식별할 때는 앱이 넘긴 **회원번호만 믿지 않는다**. 카카오에 토큰으로 `user/me`를 다시 호출해 받은 `id`만 신뢰한다.

## 목표 목록 동기화 (구현함)

### 방향

- 서버 PostgreSQL이 목표의 소스(문서: `server/docs/overview.md`, 스키마: `server/db/migrations/002_goals.sql`).
- 1차로 **서버 → 로컬**만 한다. 서버 응답으로 로컬 SQLite(`goals`)를 **통째로 교체**한다(서버 `id`가 앱 행 `id`로 들어감). 서버에 없는 로컬 목표는 동기화 시 사라진다.

### 서버 API

- `POST /login/` — 본문 `{ "accessToken": "…" }`. 카카오에서 사용자 확인 후 `users`에 **kakao_id 기준 upsert**(`insert … on conflict (kakao_id) do update`). 응답 `{ "kakaoId", "email" }`.
- `POST /goals/list/` — 동일하게 `accessToken`으로 사용자 확인 후, 해당 `user_id`의 `goals`를 최근 등록순으로 JSON 배열로 반환. 필드명은 camelCase(`responseJson`, `createdAt`, `startAt`, `endAt`, `verdict`, `verdictReason`, `verifiedAt`).
- 개발 편의: `DEBUG=True`일 때 `ALLOWED_HOSTS = ['*']`.

### 앱

- `.env`에 **`ENABLE_SERVER_SYNC=true`** 와 **`API_BASE_URL=http://<호스트>:8000`** 이 둘 다 있을 때만 동기화한다(테스트·개발 시 실수로 빈 서버에 맞춰 로컬이 지워지는 것을 방지).
- 실기기 안드로이드: PC와 같은 Wi‑Fi에서 PC의 LAN IP를 쓴다. PC에서 `runserver 0.0.0.0:8000` 등으로 바깥에서 접속 가능하게 둔다.
- HTTP 사용 시 Android `application`에 `android:usesCleartextTraffic="true"` 적용됨.
- 동기화 호출: `main` 직후(토큰 있을 때), 홈 `_loadGoals` 직전, 로그인 화면에서 이미 로그인된 경우·카카오 로그인 직후, 내정보에서 홈으로 돌아올 때(프로필 닫은 뒤).

### 테스트

- 위젯 테스트에서는 `GoalSyncService.allowSync = false`로 두어 번들 `.env`에 동기화가 켜져 있어도 메모리 DB가 비지 않게 했다.

## 롤백했던 것 (이전 논의)

- 디버그용 로그인 정보 삭제, 동의 항목 전부 표시, 내정보에 액세스 토큰 출력, 서버 연동 시도 초안 등은 사용자 요청으로 롤백한 적이 있다. 이후 목표 동기화는 위와 같이 다시 설계·구현했다.
