## Django를 기존 PostgreSQL에 연결

Django 기본 설정은 SQLite다. `config/settings.py`는 `db.sqlite3`를 가리킨다. 계정과 목표 표는 이미 로컬 PostgreSQL `do_or_die`의 `users`, `goals`에 있다. 다음 작업은 이 설정을 그 데이터베이스로 바꾸는 것이다.

접속에는 비밀번호가 필요하다. 이 비밀번호는 서버 전용 PostgreSQL 역할의 비밀번호다. 저장소 밖 환경 파일에 두고, `settings.py`와 git에는 넣지 않는다. 운영체제 사용자 `petercha`는 PostgreSQL 역할이 아니다. `postgres` 운영체제 계정으로 이 프로세스를 실행하지 않는다.

### 지금까지

1. 스키마 설명과 실행 SQL을 서버 저장소 `docs/schema.md`, `db/migrations`로 옮겼다.
2. `server/.venv`에 Django 6.1.2를 설치했다.
3. `startproject`로 `manage.py`와 `config/`를 만들었다.
4. Django 기본 사용자, 세션, 관리 화면을 설정에서 뺐다. `migrate`는 실행하지 않았다.
5. 서버 git 저장소를 만들고 GitHub `petercha31/do-or-die-server`의 `master`에 올렸다.

데이터베이스 설정은 아직 SQLite다.

### 작업 순서

1. PostgreSQL에 서버 전용 역할을 만들고 비밀번호를 부여한다. 그 역할이 `do_or_die`의 `users`와 `goals`를 읽고 쓰게 한다.
2. 비밀번호, 데이터베이스 이름, 역할 이름, 호스트, 포트를 저장소 밖 환경 파일에 둔다.
3. 가상환경에 PostgreSQL 드라이버 `psycopg`를 설치한다.
4. `settings.py`의 `DATABASES`를 PostgreSQL로 바꾼다. 접속 값은 환경 파일에서 읽는다. 호스트는 로컬이다.
5. 연결만 확인한다. `users`를 읽는 정도다. 이 단계에서 `migrate`는 실행하지 않는다. `migrate`는 이미 있는 `users`와 `goals`를 만드는 명령이 아니고, `django_migrations` 표를 추가한다.

연결이 확인되면 10월 30일 회의의 로그인 확인으로 간다. 같은 카카오 액세스 토큰으로 로그인 요청을 두 번 보낸다. 첫 요청에서 `users` 행이 생기고, 둘째 요청에서는 그 `kakao_id`의 행이 하나인 채로 남으면 된다. 목표 API와 앱 연결은 그 다음이다.
