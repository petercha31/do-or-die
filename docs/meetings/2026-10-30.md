# 2026-10-30

## 계정 저장 서버

로컬 `do_or_die` 데이터베이스에 `users`와 `goals`가 있다. 앱의 목표 원본은 아직 휴대폰 SQLite다. 카카오 로그인은 앱에서 회원 정보를 보여줄 뿐, 서버 계정을 만들지 않는다.

### 서버

계정 저장 서버는 Flutter 저장소와 git 저장소를 따로 둔다. 로컬에서는 `do-or-die/` 아래에 `app/`과 `server/`를 나란히 둔다. `do-or-die/` 자체는 git 저장소가 아니다. 구현은 Django다. Django 기본 사용자와 세션은 쓰지 않고, 이미 만든 `users`와 `goals`를 쓴다.

듣는 주소는 로컬로 한정한다. 데이터베이스에는 서버 전용 역할로 접속하고, 그 비밀번호는 저장소 밖 환경 파일에 둔다. `postgres` 운영체제 계정으로 이 프로세스를 상시 실행하지 않는다.

### 로그인 요청

앱이 카카오 액세스 토큰을 서버에 보낸다. 서버는 그 토큰으로 카카오 사용자 정보 API를 호출해 회원 번호와 이메일을 받는다. 앱이 보낸 회원 번호는 계정 기준으로 쓰지 않는다.

`users.kakao_id`로 행을 찾는다. 없으면 만든다. 이메일은 카카오가 준 경우에만 소문자로 저장한다.

서버는 서명한 토큰을 돌려준다. 토큰에는 우리 `users.id`가 들어간다. 로그인 토큰 표는 만들지 않는다.

응답 계정 키는 `id`, `kakaoId`, `email`, `createdAt`이다.

### 확인

앱을 서버에 붙이기 전에 확인한다. 같은 카카오 액세스 토큰으로 로그인 요청을 두 번 보낸다. 첫 요청에서 `users` 행이 생기고, 둘째 요청에서는 그 `kakao_id`의 행이 하나인 채로 남으면 된다.

앱이 토큰을 안전 저장소에 넣고 목표 요청에 싣는 일은 서버 목표 API를 확인한 뒤 한다.
